# 예측·ML 과제 지침

별도 지시가 없으면 CPU에서 빠르게 학습·추론되는 방법만 쓴다. 학습 1회 2분 이내, 화면 요청 1회 추론 1초 이내를 목표로 한다. 딥러닝, AutoML, GPU 전제 방법은 쓰지 않는다.

## 순서
1. 문제 정의: 구현 전에 아래를 질문 형태로 사용자에게 제시하고 답을 기다린다.
   - 예측 대상과 라벨 정의, 예측 시점(이후 데이터는 특징으로 쓰지 않는다), 예측 후 하는 행동, 놓침과 헛경보 중 무엇이 더 비싼가, 하루 감당 가능한 경보 수
   - 예측이 아니라 최적화·규칙 문제로 보이면 ML을 억지로 쓰지 말고 그렇게 말한다.
2. 데이터 점검: 라벨 비율, 파일 간 연결 키, 시간 범위, 결측. 특징마다 `예측 시점 이전에 알 수 있는가 / 근거`를 표로 만들고, 제외 여부는 사용자가 정한다.
3. 분할: 시간순 또는 lot·장비 같은 그룹 단위. 이유 없이 무작위 분할하지 않는다. 평가 데이터는 마지막 비교 전까지 쓰지 않는다.
4. 기준선 먼저: 다수 클래스·평균, 직전값, 사용자·담당자 규칙, 관리 한계(평균±3σ) 이탈. 첫 E2E 버전에는 기준선을 연결하고 `predict()` 하나로 교체되게 만든다.
5. 후보는 아래에서 최대 2개:
   - 표 데이터 + 라벨: 로지스틱 회귀, LightGBM(또는 XGBoost `tree_method="hist"`). `n_estimators` 300 이하, 조기 종료, `n_jobs=-1`
   - 라벨 없음: 관리 한계(z-score), IsolationForest
   - 시계열: 이동평균·직전값 기준선 → 과거값(lag) 특징 + GBDT
   - 웨이퍼맵 격자: 영역별(중심·중간·가장자리, 반경·각도) 불량 밀도 특징 + GBDT. 좌표 기준은 데이터에서 확인하고 중심은 직접 계산한다
   - 텍스트·희소 고차원·클래스 다수: TF-IDF + 로지스틱 회귀 또는 SGD 선형 모델
   - 불균형: `class_weight` 또는 `scale_pos_weight`. 오버샘플링은 쓰지 않는다
6. 평가: 불균형이면 정확도를 쓰지 않는다. PR-AUC, 재현율·정밀도, 혼동행렬. 회귀는 MAE. 기준선 포함 같은 분할로 `모델 / 지표 / 학습 시간 / 추론 시간 / 설명 가능성` 비교표를 만든다. 결과가 지나치게 좋으면(예: 0.99) 누수부터 의심해 보고한다. 표와 함께 추천 모델 하나를 이유와 함께 제시하고 사용자가 고른다.
7. 임계값: 0.5를 기본으로 쓰지 않는다. 허용 경보 수·비용 기준 후보 2~3개와 각각의 재현율·정밀도를 표로 제시하고 사용자가 고른다(DECISIONS에 `[사용자]`).
8. 설명: 전체 특징 중요도와 건별 상위 기여 요인 2~3개를 API와 화면에 제공한다. 보정하지 않은 확률은 "위험 점수"라고 부른다.
9. 실행: 학습은 `scripts/train.py`로 분리하고 모델 파일을 저장한다. 앱은 저장된 모델을 불러오기만 한다. 2분이 넘을 학습은 직접 돌리지 말고 사용자에게 다른 터미널에서 칠 명령을 준다. 시드를 고정한다.
10. 기록: DECISIONS에 분할 방식, 비교표, 선택 이유, 임계값. 한계에 데이터 기간, 공정 변화(드리프트), 라벨 품질, 재학습 주기.
