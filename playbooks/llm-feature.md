# 제품 안 LLM 기능 지침 (챗봇, 요약, 자연어 질의, 에이전트)

- LLM 호출 방식(API 키, `codex exec` 등)은 과제나 운영진 안내를 따른다. 안내가 없으면 임의로 정하지 말고 사용자에게 묻는다. 어떤 방식이든 키·토큰은 코드와 커밋에 넣지 않는다.
- 구조는 질문 범위로 정한다. 정해진 몇 가지 질문이면 좁은 도구 + 단순 반복 루프로 직접 짠다. 임의 질문에 코드를 짜서 답해야 하는 열린 분석이면 기존 에이전트(opencode·pi, 제공된 `codex exec`, 에이전트 SDK 등)를 쓰는 안도 선택지로 낸다.
  둘을 `신뢰성 / 응답 속도 / 비용 / 보안 / 설명 가능성 / 붙이는 데 드는 시간`으로 비교한 표와 함께, 과제 요구에 비춰 추천안 하나를 이유와 함께 제시하고 사용자가 고른다. 기존 에이전트를 쓰면 데이터는 읽기 전용 사본만 주고, 쓰기 권한은 최소로, 시간 제한을 건다.
- 직접 짜는 루프의 도구는 좁은 읽기 전용 함수로 만든다(예: `get_lot_history(lot_id)`). 쓰기 동작은 과제가 요구할 때만, 사용자 확인 단계를 둔다.
- 계산과 판정은 코드가 한다. LLM은 질문 해석, 도구 선택, 결과 설명만 맡는다.
- 안전장치: 최대 반복 5회, 호출 타임아웃, 출력 형식은 JSON 스키마로 고정, 실패하면 사용자가 이해할 수 있는 메시지.
- 응답마다 호출한 도구·인자·결과 요약을 함께 반환하고 화면에 근거로 보여준다.
- 핵심 화면은 LLM 없이도 동작하게 만들고, LLM은 "자연어로 묻기" 같은 추가 입구로 둔다. LLM 호출이 실패해도 데모가 무너지지 않아야 한다.
- 평가: 질문 5~10개와 기대 답으로 정답률을 재고 DECISIONS에 기록한다. 호출 수와 토큰 사용량도 보고한다.
