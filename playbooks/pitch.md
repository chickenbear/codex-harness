# 피칭 지침 (사용자가 "피칭"이라고 하면, 파일로 만들지 말고 답변으로)

근거는 PLAN·DECISIONS·OPEN, `git log`, 실제 실행 결과만 쓴다. 없는 성과나 숫자를 만들지 않는다.

## 발표 구조 (3분 기준, 시간이 다르면 비율 유지)
1. 문제 (20초): 누가, 언제, 무엇 때문에 곤란한가. 담당자 말 인용 1개
2. 문제 정의와 범위 (30초): 무엇을 하고 무엇을 뺐나, 그 이유
3. 해결 방식 (40초): 데이터 흐름 한 줄, 핵심 규칙·모델 2~3개
4. 데모 (60초): 클릭 순서 3~5단계와 각 단계에서 보여줄 것, 화면이 깨질 때 대체 경로
5. 검증 근거 (20초): 숫자 2~3개 (기준선 대비, 실제 사례 재현 등)
6. AI와 일한 방식 (10초): AI 제안을 사용자가 바꾼 사례 1개 (수정 기록에서만)
7. 한계와 다음 단계 (10초)

## 함께 줄 것
- 예상 질문 5개와 각 30초 답변. 심사위원(AI·반도체 전문가) 관점: 데이터 누수, 현장 적용성, 확장성, 비용, 안전
- 데모 사전 점검: 서버 실행 명령, 데모용 경로와 입력값, 깨지기 쉬운 지점
- 슬라이드는 사용자가 요청할 때만 만든다
